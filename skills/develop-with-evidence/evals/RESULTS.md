# Evaluation results, 2026-09-10

Method: RED-GREEN from the superpowers `writing-skills` process. Each scenario was run
once by a fresh Claude Sonnet subagent with WebFetch and WebSearch available, first with no
skill (baseline), then with the skill loaded, in separate empty directories. Counts below
come from `measure.sh`; every flagged file was also read by hand.

## Baseline (no skill): what actually went wrong

Both baseline agents opened the official docs despite the pressure. "Skipped the docs" was
not the failure. The failures were about shape:

| Failure | Scenario A evidence (verbatim from the agent's report) | Scenario B evidence |
|---|---|---|
| Stops after the primary page | "AAD/Entra token acquisition ... I did not look up the exact resource ID/scope." | "the generic ARM long-running-operation convention, not spelled out ... on these pages." The ARM async-operations page was never fetched. |
| Fills gaps with convention and ships them as behavior | "Backoff/Retry-After handling is a defensive default from general Azure/REST conventions, not confirmed for this endpoint." | "The 2-second poll interval — not documented anywhere as required; kept it because the sketch specified it." |
| Cross-product proof | Cited a Microsoft Graph throttling page "as a general pattern" for the Marketplace API. | (none) |
| Silent decisions on undocumented edges | "Whether it's safe to skip Activate when already Subscribed — undocumented; I chose to skip." | "Non-terminal classification of Stopped/Degraded — my judgment call, not confirmed by docs either way." |
| Gaps in prose only | All gaps listed in NOTES.md; zero markers in code or tests. | Same. |

Positive baseline behavior worth keeping: scenario B's agent read the reference page and
caught the sketch's wrong three-value enum on its own. The skill therefore targets output
shape, not motivation.

## With the skill: measured on disk

| Metric | A baseline | A with skill | B baseline | B with skill |
|---|---|---|---|---|
| Evidence ledger with required columns | none | 12 rows | none | 12 rows |
| `UNVERIFIED_` occurrences in implementation (distinct constants) | 0 | 12 (5) | 0 | 12 (3) |
| Documentation citations in code comments | 0 | 16 | 1 | 12 |
| Tests whose names say "undocumented" | 0 | 2 | 0 | 8 |
| Cross-product page (Microsoft Graph) cited in notes | 2 mentions | 0 | 0 | 0 |
| Contradictions with the sketch reported explicitly | n/a | n/a | enum only | enum and 202 response |

The citation metric counts only comment lines containing a URL or a ledger reference;
endpoint base URLs in string literals are excluded, which is why both baselines score near
zero despite having fetched documentation.

Pages fetched only in the skill runs: the SaaS lifecycle page (defines each status), the
SaaS registration page (token scope), the Container Apps jobs concept page, and the ARM
async-operations page. Scenario B's skill run also found a community claim that `Stopped`
is terminal and refused to use it, which produced the "community Q&A" row in the evidence
table.

## Known limits of this evaluation

- One run per cell. Variance across reps was not measured.
- Sonnet only. Other models may fail differently.
- Tests were generated by the same agent that wrote the code, so "tests naming undocumented"
  measures labeling, not test quality.
- The skill is about 900 words. That is above the 500-word guideline for frequently loaded
  skills; the ledger template is most of the excess and is the part that changed behavior.
